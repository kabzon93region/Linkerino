## Контракты

- `Plan BuildPlan(source_input, dest_parent_input)` — только читает; при ошибке `valid=false` и русский текст в `error`.
- `Outcome Execute(plan, sink, faults)` — вызывается из рабочего потока; пишет журнал; `leftover` указывает, где остались данные; `needs_elevation` — не хватило прав на ссылку.
- `ProgressSink::OnProgress` вызывается из рабочего потока (GUI копирует данные и пересылает сообщением); `CancelRequested` опрашивается только до фазы `Publish`. Повторная проверка копии перед удалением идёт без опроса отмены (`cleanup_context` без sink).
- `Faults` — только для тестов: `copy_failure`, `verify_mismatch`, `link_failure`, `low_space`, `touch_source_after_copy`, `tamper_after_publish`, `break_link_before_delete`, `force_flush_failure`, `break_link_after_files`.
- Журнал: `%LOCALAPPDATA%\Linkerino\journal-<guid>.txt`, состояния `start`, `copying`, `verified`, `published`, `backup`, `linked`, `cleanup-partial`, `cleanup-skipped`, `cleanup-skipped-durability`, `link-lost`, `failed`, `cancelled`, `relink-failed`. Только для информирования пользователя; автоматических действий по журналу нет.

## Поток выполнения

`BuildPlan` → `Execute`:

1. Preflight: `ProbeSymlink` (пробная ссылка рядом с исходной папкой), проверки занятости служебных имён, создание staging.
2. `ScanDir` → `std::vector<Entry>` (pre-order): идентификатор файла, размер, даты, атрибуты, сигнатура DACL, потоки; отказ на reparse/EFS/offline/жёстких ссылках и потоках на каталогах. После скана проверяется свободное место на томе назначения.
3. `CopyTree` → staging: данные и потоки с SHA-256 и `FlushFileBuffers`, DACL как явный (protected) ACL, даты, атрибуты.
4. `VerifyTree` — набор путей (сортировка, без зависимости от порядка перечисления), типы, размеры, даты, DACL, хэши; `VerifySourceUnchanged` — идентификаторы, размеры, даты, DACL и хэши источника.
5. `RenameWithRetry(staging → dest_final)` — публикация (с повторами при кратковременной блокировке), фиксация серийного номера тома и индекса каталога, `FlushVolume` (best effort).
6. `MoveFileEx(source → backup)` → `CreateSymbolicLinkCompat` → `VerifySymlink` (тег `IO_REPARSE_TAG_SYMLINK`, цель, открытие и совпадение идентификатора каталога).
7. Перед удалением: повторная проверка ссылки и полная повторная сверка опубликованной копии (без опроса отмены); при расхождении удаление не начинается. Затем `FlushVolume` (дескриптор тома): без подтверждения записи резерв сохраняется и пользователю сообщается, что старое место не освобождено.
8. `DeleteBackupTree` — обратный обход: повторная проверка идентификатора, размера, даты и хэшей перед удалением каждого файла, проверка ссылки каждые 32 элемента; при расхождении удаление прекращается, остаток резерва сохраняется, а при пропаже ссылки итог помечается как незавершённый.

## Инварианты

- До публикации исходная папка не изменяется.
- Любое удаление предваряется повторной проверкой; при расхождении удаление прекращается и путь остатка показывается пользователю.
- DACL копируется без наследования от новой папки; сравнение не зависит от флага наследования ACE на разных томах.
- Дескрипторы перечисления закрываются только `FindClose` (`FindHandle`): `CloseHandle` оставлял дескриптор и блокировал переименование каталога — ошибка найдена тестами и исправлена.
- При неудачной ссылке исходное имя восстанавливается; проверенная копия не удаляется.
- Отмена не прерывает переключение: кнопка гасится на фазах `Publish`, `Link`, `Cleanup`.

## Ограничения, заложенные в код

- `kMaxStreamPath` (`MAX_PATH - 32`, 228 символов) — ограничение `FindFirstStreamW`, длиннее — отказ.
- Только локальные NTFS-тома; сеть и другие ФС отклоняются в `BuildPlan`.
- `ProbeSymlink` требует прав; без них перенос не начинается, предлагается перезапуск.
- Подтверждение записи возможно только через дескриптор тома (нужны права администратора); иначе резерв сохраняется.
- Копия полностью сверяется один раз перед удалением; во время самого удаления проверяется доступность ссылки каждые 32 элемента. Изменения копии в этом окне не отслеживаются.
